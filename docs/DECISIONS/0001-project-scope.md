# ADR 0001: Cirvane product scope and claim boundary

- **Status:** accepted
- **Date:** 2026-08-24

## Context

The verified Nucleus v2 prototype requires an enduring name, independent private repository, product-grade identity and authenticated update path. A possible future novel kernel must not force another rebrand or inflate current claims.

## Decision

Use Cirvane as the maturity-neutral product identity. This ADR originally selected ESP-IDF/FreeRTOS for the initial developer release and treated a clean-sheet kernel as optional later research. ADR 0002 later made a clean-sheet kernel a blocker for a kernel-labelled release. ADR 0005 restores ESP-IDF/FreeRTOS as the substrate of the first labelled Cirvane firmware, with an honest claim. Identity and claim-discipline decisions here remain in force.

## Consequences

Current performance and security evidence can be preserved with explicit historical provenance. Cirvane must not be called a novel kernel or production-ready. The name requires formal trademark review before public opening.
